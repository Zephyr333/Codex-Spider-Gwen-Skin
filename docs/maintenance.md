# Spider-Gwen 维护说明

2.1.0 保留当前壁纸和视觉效果，将正常更新改为事件驱动。常见组件变化由局部识别收敛；未知结构保留原生操作，并通过诊断明确报告，避免猜测布局。

## 首先检查

通过已加载脚本的 `selfCheck()` 获取功能、结构、视觉三个结果。`getDiagnostics()` 是缓存结果，不代表重新完成视觉验收；查看 `visualCheckedAt`、`visualIssues`、`modules` 和 `missing`。

`metrics.fullScans` 统计完整外壳识别，`componentUpdates` 统计局部组件集合更新，`geometryUpdates` 统计几何更新，`healthChecks` 统计轻量兜底。显式 `ensure()` 和 `selfCheck()` 会主动重新识别，应从空闲性能比较中排除。

性能采样默认关闭。需要时先调用 `startPerformanceSampling()`，完成同一页面和操作流程后调用 `stopPerformanceSampling()` 取回数据。记录最多 200 条，仅含阶段及耗时；诊断与采样没有上传或持久化行为。

普通几何更新使用布局观察器提供的矩形快照；显式自检仍读取当前真实几何。不要将同步 `getBoundingClientRect()`、页脚历史探测或装饰样式写回塞进每次输入高度变化。主页快并不能证明长会话也快，必须分别采样。

## 修改位置与约束

- `src/runtime.js`：语义锚点、模块缓存、失效信号、组件识别、所有权清理和诊断。新增回退须有真实结构证据和 fixture，保持未知组件原生。
- `src/skin.css`：主题变量和受控视觉层。材质由逻辑外壳统一绘制，内部文字、图标及标题伪元素不得重复承担背景；保留原生布局、事件和 ARIA。
- `src/compatibility.css`：已证明必要的独立修复。仅凭圆角、通用背景类或节点顺序不能隐藏、移动原生控件。

不要不断复制更长选择器，也不要修改 Codex/Codex++ 安装文件。不要为失配组件重建按钮、替代事件，或给原生按钮统一固定尺寸。装饰尺寸和侧栏避让使用自有变量，销毁时只恢复本脚本仍拥有的写入。

## 验证与部署

运行 `npm test`、`npm run build`、`npm run check`。完整回归包含约一分钟的流式输出观察，不能把短期通过描述为长期运行证明。

功能、结构、视觉、性能分别记录结果。实机检查真实菜单、键盘展开、侧栏折叠、输入框和六种首页/会话组合；不要发送测试消息或更改模型设置。旧视觉基线不覆盖，新截图另存。

性能比较使用同一页面类型、窗口尺寸和操作流程。区分冷启动、显式自检和正常局部更新；脚本阶段耗时包含同步样式与布局成本，不等于整个客户端 CPU 或帧率。

部署使用 `node scripts/manage.mjs deploy --apply`，保留校验备份，通过 Codex++ 正常入口重载，再核对 `sourceSignature` 和安装文件 SHA-256。回退使用对应备份的 `restore --backup ... --apply`，先确认 dry-run 通过。

## 已知验收边界

快速模式或额度提示是否出现取决于应用状态。已有结构回归不等于这些真实业务状态都已实机验证。未来上游彻底更换语义结构或底座规则仍可能需要维护，目标是降低维护频率并保持原生可用。
